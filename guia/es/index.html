Claude Code · sesiones concisas

Mira la cuota real y nunca pierdas el hilo en el /clear

Statusline que muestra el contexto, la cuota de 5 h, la cuota semanal general y la semanal por modelo. Tres skills que completan el ciclo: checkpoint, auditoría de memoria y handoff.

Qué es

Tres piezas que se comunican

El modelo no puede ver su propia cuota. La barra sí. Las skills usan lo que muestra la barra para decidir cuándo compactar, auditar o entregar la sesión al siguiente agente.

📊 Statusline con cuota real

Lee el endpoint oficial de uso y muestra ctx, 5h, w (semanal general) y F (semanal del modelo en uso, con ! en alerta). Caché de 300 s para no martillar la API.

🧩 Skills de sesión

session-statusline (checkpoint), memory-audit (qué conservar, comprimir, borrar) y session-handoff (resumen para el próximo agente). Como apoyo: maestro-roteador (modelo y esfuerzo) y fable-mindset (playbook a partir de los registros).

🗺️ Plan de optimización

Activadores leídos directamente de la barra: contexto 40/60/80 %, cuota de 5 h, cuota por modelo. Reglas de higiene y qué medir para saber si está funcionando.

Cómo funciona

El ciclo de una sesión

La barra sube y haces un checkpoint. Si hay mucho ruido, audita y compacta. Si vas a limpiar, entrega el handoff y pégalo en la nueva sesión.

trabajar→ ctx sube→ checkpoint→ memory-audit→ /compact→ handoff→ /clear
1

Checkpoint

Vista rápida: foco actual, qué quedó guardado × candidato a memoria, próximos pasos y una recomendación (continuar, compactar, auditar, handoff).

2

Auditoría de memoria

Inventario del contexto y del CLAUDE.md. Clasifica cada elemento como conservar, comprimir, mover o borrar. Solo lo guarda si lo pides.

3

Handoff

Resumen estructurado con rutas absolutas, procesos en segundo plano, comandos de verificación y un "retoma desde aquí". Sin retrospectiva.

Requisitos previos

Lo que debe estar en la máquina

Todo local. El script lee el token OAuth del propio Claude Code y solo se comunica con el endpoint oficial de uso.

Claude Code con sesión iniciada

Inicio de sesión mediante claude.ai (OAuth). El token queda en ~/.claude/.credentials.json.

claude # y /login si aún no lo hiciste

jq + curl

El script depende de ambos para leer el payload y llamar a la API.

sudo apt install jq curl

El repo

Clona y pega los prompts, o copia los archivos manualmente.

git clone https://github.com/inematds/claude-session-kit.git
Guía de uso · paso a paso

Del clon a la barra funcionando

Cada paso tiene el comando real. Si lo prefieres, los prompts del repo lo hacen por ti dentro de una sesión de Claude Code.

1

Instala el script de la statusline

Copia el script a la carpeta de Claude Code y dale permiso de ejecución.

cp statusline/statusline-command.sh ~/.claude/statusline-command.sh
chmod +x ~/.claude/statusline-command.sh
2

Apunta settings.json al script

Combina el bloque de abajo con tu ~/.claude/settings.json (no borres las otras claves). O pega statusline/PROMPT.md en una sesión y deja que Claude lo haga.

{
  "statusLine": { "type": "command", "command": "bash ~/.claude/statusline-command.sh" }
}
3

Prueba la renderización

Ejecuta el script con un payload mínimo y verifica la línea.

echo '{"cwd":"'$PWD'","model":{"display_name":"Fable 5.1"}}' | bash ~/.claude/statusline-command.sh
# user@host:~/proj Fable 5.1  ctx 41%  5h:2%→19:10  w:69% F:80%!→14/09 21:00  d:40.9M
4

Lee la barra

Cada campo tiene un significado y un desencadenante en el plan.

ctx 41%          # % de la ventana de contexto usada en esta sesión
5h:2%→19:10      # límite de 5 horas y hora local del reinicio
w:69%            # límite semanal de todos los modelos (weekly_all)
F:80%!           # límite semanal del modelo en uso (weekly_scoped) — "!" = alerta
→14/09 21:00     # cuando se reinicia el límite semanal
d:40.9M          # tokens del día, contados en los JSONL locales
5

Instala las skills

Copia las carpetas a ~/.claude/skills/, o pega skills/PROMPT-instalar.md en una sesión.

cp -r skills/session-statusline skills/memory-audit skills/session-handoff ~/.claude/skills/
cp -r skills/maestro-roteador skills/fable-mindset ~/.claude/skills/   # apoyo: modelo/esfuerzo y playbook
ls ~/.claude/skills | grep -E 'session|memory|maestro|fable'
6

Usa el ciclo

Di estas frases durante la sesión. Cada una activa la skill correcta.

checkpoint            # o "dónde estamos" → session-statusline
analise a memória     # o "memoria inflada" → memory-audit
handoff               # o "voy a ejecutar /clear" → session-handoff, luego /clear y pega el resumen
qual modelo uso?      # cuando F: está con "!" → maestro-roteador
analisar minhas sessões # playbook por modelo a partir de los JSONL → fable-mindset
Ejemplos

Activadores leídos de la barra

De PLANO-OTIMIZACAO.md. La barra es el sensor; la tabla es la regla.

ctx 40–60 %

checkpoint. Decide si compactas ahora o sigues.

ctx > 60 % o salida repetitiva

memory-audit → aplicar el plan de optimización → /compact.

ctx > 80 %

handoff → /clear → pegar el handoff en la sesión nueva.

F: con "!"

maestro-roteador decide qué va a un modelo más barato (/model o subagente). El resto espera el reinicio indicado en la barra.

La teoría detrás del kit está en el curso Maestro en Contexto y Tokens: releer el contexto, prompt caching, rutina de /clear e /compact, handoff y subagentes. Plugins compatibles con el ciclo (no incluidos): context-mode, claude-mem, claudex.
